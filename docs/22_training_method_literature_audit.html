1감사 방법과 인용 규칙

질문은 "우리 학습 방법이 참고 연구들의 학습 방법과 맞는가"이므로, 2차 자료 없이 원문만 근거로 삼았다.

  • 원문 확보: 각 논문의 arXiv HTML/ar5iv 전문(본문+보충자료)을 내려받아 대조. 판본 명기(예: SAM-6D는 arXiv v2). 로컬 검증 사본은 작업 스크래치에 보존.
  • 인용 형식: 본문 주장마다 [n, §절/Eq.(식)]. 핵심 주장에는 원문 인용구(영문, ≤25단어)를 보라색 인용 블록으로 병기. 원문 오탈자는 [sic]로 보존.
  • 부재의 검증: "논문이 X를 안 한다"는 주장은 전문 문자열 검색(예: symmetr*)으로 부재를 확인한 경우에만 기재. 확인 못 한 것은 §7 미확인 대장에 남긴다 — 관례값을 채워 넣는 것은 날조다.
  • 우리 측 근거: 코드 파일:행(git 0ccb5dc)과 실측 리포트(reports/{tag}/metrics.json)로 인용. 논문에 없는 사실(예: MegaPose-GSO 물체별 리스케일)은 "당측 실측"으로 출처를 구분한다.

3연구별 학습 방법 원문 대조

3.1 SAM-6D[1] — 직접 비교 대상 (우리 클린룸 재구성의 원형)

무엇을 학습하나: 분할부(ISM)는 전체가 무학습이고, 포즈부(PEM)만 학습한다.

[1, §1]"ISM, built on SAM, does not require any network re-training or fine-tuning"

PEM 구조: ViT-Base 특징(3·6·9·12블록 concat)[1, 보충 §B.1.1] → coarse 매칭(GeoTransformer 블록×3, 196점) → fine 매칭(SDPT×3, 2048점). 소프트 할당은 학습 bg 토큰을 붙인 행렬의 행·열 softmax 곱이며, 온도 τ 값은 논문에 명시가 없다[1, Eq.(5)(6)].

[1, §4]"we set N_m^c=N_o^c=196 and N_m^f=N_o^f=2048" — 우리 코어스 196은 이 수치를 그대로 따른 것.

손실은 InfoNCE(=행·열 CE) 하나뿐이고, 전 트랜스포머 블록 출력에 심층 감독한다. 포즈 회귀 손실은 없다(포즈는 비학습 weighted SVD).

[1, 보충 §B.2 Eq.(12)(14)]"L = CE(A[1:,:], Ŷ_m) + CE(A[:,1:]^T, Ŷ_o)" · 6개 블록 합산 최적화

대응 라벨: GT 포즈로 관측점을 물체계로 보내 최근접 인덱스, 거리<δ_dis=0.15(단위구 정규화 좌표)이면 그 인덱스, 아니면 배경(0번) — 우리 라벨 규칙과 동형(우리는 0.10·직경).

[1, 보충 §B.2 Eq.(13)]"we set δ_dis as a constant 0.15, since both P_m and P_o are normalized to a unit sphere"

대칭: 학습 라벨에서 대칭 처리 명시 없음이 검증됨 — symmetr* 어휘는 전문에서 평가 지표(MSSD/MSPD) 소개 1곳뿐. 데이터: MegaPose 제공 합성 2백만 장·약 5만 물체, RGB-D[1, §4]. 템플릿: 학습 2뷰, 평가 42뷰(CNOS 준거).

[1, §4]"For each object, we use two rendered templates for training PEM."

최적화: Adam, 600k iter, lr 1e-4 cosine, bs 28[1, §4]. PEM ViT의 사전학습 출처·동결 여부는 명시 없음(§7 대장).

3.2 GeoTransformer[2] — SAM-6D coarse 블록의 원 논문

손실은 overlap-aware circle loss(superpoint) + NLL/dustbin(point)의 합[2, §3.5 Eq.(14)(15)]. CE 대신 메트릭러닝을 택한 근거로 "CE 다중라벨 분류가 고신뢰 양성을 억제한다"는 그래디언트 분석을 제시한다[2, Appx C] — 우리 CE 채택과의 설계 분기점(§5-C2). 라벨은 패치 중첩 ≥10% 양성/무중첩 음성/그 외 제외[2, §3.5]. 기하 임베딩은 bin이 아닌 사인파(σ_d=0.2m, σ_a=15°, k=3)[2, Appx A.1/A.3] — 우리 _DistBias(학습 16-bin)는 이를 단순화한 변형. 학습은 Adam 1e-4, 지수감쇠 0.05/ep, bs 1, wd 1e-6, 40ep(3DMatch)[2, Appx A.3], teacher forcing(GT superpoint 대응 N_g=128 샘플)[2, §3.5].

3.3 MegaPose[3] — 학습 데이터의 출처이자 대칭 회피 전략의 반례 실증

Coarse = 분류: 렌더-관측 비교로 "리파이너 수렴 영역 안인가"를 이진 CE로 학습(가설 104개 = 양성 1 + 음성 103)[3, §3.1-3.2, Appx D]. 대칭 주석 없이 학습 가능한 이유를 분류 정식화 자체에 둔다:

[3, §3.1]"Since we are performing classification, our method can implicitly handle object symmetries, as multiple poses can be classified as correct."

결정적 반례 실증: coarse를 회귀로 바꾸면 학습이 붕괴하며, 원인을 대칭 물체의 모호한 그래디언트로 추정한다 — 대칭 모호성을 라벨 수준에서 제거해야 한다는 우리 g* 설계의 문헌 근거.

[3, Appx F]"We hypothesize this failure is due to the presence of symmetric objects in our training set which leads to ambiguous gradients during training."

Refiner: 4뷰 렌더 입력, 병진 3 + 회전 6(Zhou 연속표현[11]) 출력, CosyPose형 분리 손실 — 단 대칭 정보는 미사용이고 이유는 주석 부재다:

[3, Appx B]"without using symmetry information on the objects because it is not typically not available for large-scale datasets of CAD models" [sic]

데이터: BlenderProc 합성 2백만 장, ShapeNet 20k + GSO 1k 물체, RGB 증강(Pillow: blur·contrast·brightness·colors·sharpness), 깊이 증강(blur·ellipse dropout·상관/무상관 노이즈)[3, §3.2, Appx E]. 물체 수 어블레이션: GSO 단독 1,000종 62.2 vs ShapeNet+GSO 21,000종 61.7 — 물체 1k 이후 수확 체감[3, Table 3(b)]. 옵티마이저·lr·배치는 명시 없음(V-100 32장, coarse 32h/refiner 48h만 기재)[3, Appx E]. 메시 리스케일 서술도 없음 — 공개 MegaPose-GSO의 물체별 스케일(s∈[0.10,1.43])은 당측이 데이터 파일에서 실측한 사실이다(train/recover_gso_scale.py).

3.4 FoundationPose[4] — 손실 선택의 반대 증거(InfoNCE 폐기)

리파이너(단일 뷰 렌더+관측, 공유 CNN→트랜스포머 헤드 2개)와 선택기(계층 비교)를 학습. 리파이너 손실은 Δt·ΔR(axis-angle) L2(w1=w2=1)[4, §3.3 Eq.(10)], 선택기는 pose-conditioned triplet(α=0.1, 양성 기준 회전 10° 이내, K=5)[4, §3.4 Eq.(11)-(14), 보충 §5.2]. InfoNCE는 실험 후 성능 저하로 폐기했다(ADD 91.52→89.39):

[4, §3.4, Table 6]"We also experimented with the InfoNCE loss [49] as used in [46] but observed worse performance"

데이터: 합성 전용 — Objaverse-LVIS 40k+ 물체 + GSO, ChatGPT+TexFusion 텍스처 증강, Isaac Sim 경로추적, 약 60만 장면/120만 장, 이득은 ~100만 장에서 포화[4, §3.1, §4.5 Fig.7, 보충 §5.2]. 물체를 5–30cm로 랜덤 리스케일·정규화[4, 보충 §5.2] — 스케일 정규화 관례의 명시 사례. 학습 라벨의 대칭 처리는 명시 없음이 검증됨(symmetr*는 평가 물체 속성 서술 1회뿐). 옵티마이저·lr·배치 명시 없음; 리파이너 50ep + 선택기 25ep + e2e 5ep, V100 4장 약 1주[4, 보충 §5.2].

3.5 Co-op[5] — 대응 기반 최신안 + 당측 이전 서술 정정

정정 — 문서 11의 Co-op 백본 서술 오류
이전 보고서(11)는 Co-op이 DINOv2 특징을 쓴다고 서술했으나, 원문 검증 결과 백본은 CroCo(3D 비전 사전학습 파운데이션 모델)이며 frozen이 아니라 파인튜닝된다. DINOv2는 관련연구 절에서 타 방법(GigaPose/FoundPose) 설명에만 등장(전문 검색으로 확인).
[5, §3.5]"The encoder and decoder architecture of Co-op are based on CroCo, a vision foundation model trained on large-scale datasets for 3D vision tasks"
CroCo 초기화 제거 시 coarse AR 58.4→46.4로 급락[5, §4.3 Table 2] — "기하 과제에 맞는 사전학습 초기화가 스크래치를 크게 이긴다"는 우리 a1 vs a0 실측(26.6% vs 18.3%)과 방향이 일치하는 문헌 근거.

학습 대상: coarse(패치 분류 + 오프셋 회귀의 하이브리드) / refiner(flow NLL-Laplace + certainty BCE + GenFlow형 분리 포즈 손실; β=5, γ=20) / selector(BCE, 양성=회전 5° 이내)[5, §3.4 Eq.(6)-(10), 보충 §6]. coarse 분류에 no-match 클래스를 두는 설계[5, §3.1]는 우리 bg 토큰과 같은 역할. 템플릿은 42 시점, in-plane 불변 매칭[5, §3.1, §3.4]. 데이터는 MegaPose 제공 합성셋(ShapeNet+GSO)[5, §3.4]. 학습 시 대칭 처리 명시 없음 검증(symmetr*는 평가 지표 1곳). 최적화 전체 공개: AdamW, A100 8장, coarse bs64·450ep, lr 2e-5→2e-6(워밍업 50ep), refiner bs32·clip 1e-2, selector bs16·200ep[5, 보충 §6.1-6.3].

3.6 FreeZe[6] + GeDi[7] — 무학습 노선과 그 기하 디스크립터의 원 학습법

FreeZe는 태스크 학습이 전무하다 — frozen GeDi(기하) + frozen DINOv2 ViT-g(비전, PCA 64차원)를 L2 정규화 후 연결, RANSAC+ICP로 정합[6, §3.1, §3.4-3.6, §4.1].

[6, §1]"harnesses the capabilities of pre-trained geometric and vision foundation models without requiring any training"

대칭은 추론 시에만 다룬다: Chamfer 최소 회전 후보를 렌더-DINOv2 코사인 유사도로 선별하는 SAR(+0.5 AR)[6, §3.6, Table 3]. FreeZe가 쓰는 GeDi의 원 학습: LRF 정준화 패치 → PointNet++ Siamese, hardest-contrastive 손실(FCGF 채택), SGD lr 0.1, 3DMatch 실측 실내 데이터[7, §3.1-3.2, §4.2]. FreeZe는 GeDi 학습 데이터를 "indoor scenes"로만 서술하므로 "3DMatch 학습판"은 두 논문을 잇는 추론임을 명시해 둔다(§7 대장). 우리 노선과의 관계: FreeZe는 우리와 같은 기하 우선 사상이지만 밀집 depth 전제(5k/1k 점 샘플)[6, §4.1] — 희소 LiDAR(수백 점)에서 GeDi류 패치 LRF가 성립하기 어려운 것이 우리가 학습 노선을 택한 이유(문서 17 §3).

3.7 대칭 처리 정전 · 42뷰 관례 · 백본 사전학습

대칭 처리의 계보 — 우리 선택지의 좌표:

  • PoseCNN ShapeMatch-Loss[10, §III-D Eq.(4)]: 대칭 명세 없이 최근접점 min — 포인트별 min이라 라벨 일관성이 없다. 우리 스펙(03 §9.3)이 포인트별 min을 금지한 것과 대비되는 반대 극단.
  • CosyPose 대칭 거리[13, §3.2 Eq.(2), 부록 Eqs.(15)-(17)]: 손실을 대칭군 위 min으로 정의 — "D_l(T₁,T₂) = min_{S∈S(l)} …". 샘플당 최적 대칭 원소 하나가 손실을 지배하므로 우리 g* 단일선택과 수학적으로 동치(argmin 선택 후 고정 = min 평가).
  • BOP 평가 정전[12, §2.2 Eq.(2)(3)]: MSSD/MSPD 모두 전역 대칭집합 위 min — 우리 평가식(sym_aware_rot_err_deg)과 동형. 대칭 주석은 Hausdorff 후보 + 텍스처 판단으로 제작[12, §2.3] — 우리는 메시 자동 검출(G≤16)로 같은 것을 무주석 획득.

42뷰 관례: CNOS가 Blender icosphere 42시점을 도입[8, §3.1] ("we render CAD models under 42 viewpoints"), SAM-6D 평가 42뷰[1, §4], FoundationPose 초기화 icosphere 42시점[4, 보충 §5.2], Co-op 42시점[5, §3.1] — 4편 수렴. 우리 S0 온보딩의 N_VIEWS=42는 이 관례와 일치.

백본 사전학습: DINOv2 = DINO 이미지 수준 + iBOT 패치 수준 + KoLeo + Sinkhorn 센터링, LVD-142M 큐레이션, 소형은 ViT-g에서 증류[9, §3-5]. DINOv3 = 7B 교사·LVD-1689M, 밀집 특징 유지용 Gram anchoring(ℒ_Gram, Eq.(2)), ConvNeXt T/S/B/L 증류판 존재[14, §3.1, §4, §7.2]. 단 공개 가중치 라이선스는 자체 "DINOv3 License"(Apache 아님 — GitHub README 원문 확인) — 문서 19의 초록 우선 원칙에 따라 현 학습은 timm Apache-2.0 ConvNeXt(convnext_tiny.in12k_ft_in1k)를 사용(train/encoders.py), DINOv3 증류판은 라이선스 결정(D-4 계열) 전까지 보류가 맞다.

6실행 반영

  • R1 (g* 마스터 기반) 정당성 상승: C4는 유일한 "수정" 판정 — 문헌 정전(CosyPose 고정 모델점)과 스펙(03 §9.3) 모두 위반 상태였음이 확인됨. 다음 런에서 수정.
  • R2 (뷰 6) 지위 조정: 문헌 관례(2뷰)를 벗어나는 가설 검증 실험으로 등급 조정 — 채택은 리포트 Δ(특히 bg 덤핑률·비대칭 ≤30°)로만 판단.
  • Phase B 데이터 상한 근거 확보: 물체 수는 GSO 1k에서 수확 체감[3, Table 3(b)], 이미지 수는 ~1M 포화[4, Fig.7] — GSO 잔여 861종 확보(계 1,029종)로 물체 축은 문헌 포화점 도달, 이미지 축은 47k→수십만 구간이 증분 구간.
  • 백본 라이선스 재확인: DINOv3 증류 ConvNeXt는 자체 라이선스 확정 — timm Apache 경로 유지(문서 19 결정 불변).
  • 문서 정정: 문서 11의 Co-op 백본 서술(DINOv2)을 본 문서로 정정 갈음(원문은 CroCo 파인튜닝[5, §3.5]).

7미확인 항목 대장 (정직성 원칙)

아래는 원문에서 확인하지 못한 것들이다. 보고서 본문은 이 항목들에 대해 어떤 값도 가정하지 않았다.
  • SAM-6D: 소프트 할당 온도 τ 값 · PEM ViT-Base의 사전학습 출처/동결 여부 · 이미지 증강 유무 · epoch/wd/GPU[1]
  • GeoTransformer: circle loss 스케일 γ 값 · overlap ratio 명시 산식 · 증강 세부(Predator 준거로만 기술)[2]
  • MegaPose: 옵티마이저·lr·배치 전체 · 리파이너 섭동 단위 표기 불일치(원문 "(0.02,0.02,0.05) centimeters"[sic] vs FoundationPose의 동일 수치 "m" 표기[4, 보충 5.2] — 어느 쪽이 오기인지 논문만으로 판정 불가)
  • FoundationPose: 옵티마이저·lr·배치(리파이너/선택기)
  • Co-op: selector weight decay · 학습 이미지 총수(“million” 표기 전문 0회)
  • FreeZe: 사용 GeDi 체크포인트의 학습 데이터 직접 지목 없음("indoor scenes"만) — 3DMatch 판이라는 것은 GeDi 원문[7, §4]과 잇는 추론
  • DINOv3: 논문 §7.2 본문 내 ConvNeXt 사이즈 열거 문장(HTML 절단) — GitHub/HF 모델카드로 대체 확증 · "DINOv3 License" 상업 조항 원문 미열람
  • 당측 유보: EPOS/SurfEmb 등 대칭 인지 손실 추가 계보 미조사(CosyPose·PoseCNN·BOP로 충분하다고 판단)
